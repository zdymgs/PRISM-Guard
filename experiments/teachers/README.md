# Paper teacher training and feature caches

These commands provide the teacher pipelines used by PRISM. Prepare the datasets, local manifests, ROI indexes, and pretrained weights yourself. Install the repository with `pip install -e '.[teachers]'`.

## Local resources

All paths belong to the user running the commands:

- `--work-root`: generated caches and experiment outputs.
- `--data-root`: the official datasets.
- `--pretrained-root`: local Torch and Hugging Face weights.
- `--external-root`: official model source checkouts needed for extraction.

Commands use local model files only. Torch checkpoints are read from `<pretrained-root>/torch/hub/checkpoints/`; Hugging Face snapshots use `<pretrained-root>/huggingface/hub/`. Prepare the official VideoMAEv2, InternVideo, and LaViLa source trees under `<external-root>/VideoMAEv2`, `<external-root>/InternVideo`, and `<external-root>/LaViLa`, installing their documented dependencies such as timm and einops when required.

The extraction code identifies the original VideoMAE, VideoMAEv2, InternVideo2, V-JEPA2 and LaViLa resources by repository ID, snapshot or checkpoint hash. The cross-dataset strong encoder snapshots are `OpenGVLab/VideoMAEv2-Large` (`9981a9c8f77118c421e5228e1b219468a4b0238d`) and `facebook/vjepa2-vitl-fpc16-256-ssv2` (`4aa02df83918538fc21cfaf576382fa20e489a80`). See the repository's third-party notices for their separate terms.

## Command dispatcher

`run.py` exposes the retained cache and training stages listed by `--help`. Put common path options before `--` and stage options after it. Every stage supports forwarded help without data:

```bash
python experiments/teachers/run.py mmact-strong-features \
  --work-root work/teachers --data-root data \
  --pretrained-root pretrained --external-root external -- --help
```

The workspace retains the stage-relative cache names used by the numerical implementations. User-generated receipts and arrays remain in that workspace. No datasets, caches, posterior banks or weights are included here.

## CUHK-X: 23 experts

The canonical manifest is `<work-root>/aligned_multimodal/data/manifest.csv`; three subject-disjoint fold files are in `data/subject_folds/fold_0.csv` through `fold_2.csv`. The extraction manifest `data/single_split.csv` contains local modality directories. ROI indexes use `aligned_multimodal/runs/dir_multiscale_roi_full/`.

The seven families have a fixed order:

| Family | Experts | Training implementation |
|---|---:|---|
| foundation | 16 | foundation source-calibrated feature heads |
| skeleton | 1 | skeleton skeleton model |
| thermal | 1 | thermal thermal model |
| token | 2 | token video token heads |
| irthermal | 1 | irthermal IR/thermal head |
| lavila | 1 | lavila LaViLa token head |
| physical | 1 | physical physical token head |

Cache stages in `run.py` are `cuhkx-aligned-cache`, `cuhkx-pixel-cache`, `cuhkx-foundation-cache`, `cuhkx-vjepa-cache`, `cuhkx-lavila-cache`, and `cuhkx-lavila-check`. The aligned cache supplies skeleton's `skeleton_float32.npy` and metadata. Four frozen physical feature caches are generated with:

```bash
python experiments/teachers/cuhkx_cache.py ir-videomaev2 \
  --work-root work/teachers --pretrained-root pretrained \
  --external-root external --output work/teachers/runs/videomaev2_distilled_teacher
```

The other backbone choices are `ir-internvideo2`, `depth-videomaev2`, and `thermal-videomaev2`; their workspace output directories are respectively `runs/internvideo2_l_k400_teacher`, `runs/videomaev2_depth_fold0`, and `runs/videomaev2_thermal_fold0`.

Train each family with the original source-only fitting recipes and nested subject splits:

```bash
python experiments/teachers/cuhkx_bank.py foundation \
  --work-root work/teachers --pretrained-root pretrained \
  --output work/banks/foundation
```

Repeat for the other families. `thermal` also takes `--thermal-manifest` (training rows with IDs, users, source labels and trial directories) and `--thermal-fold-manifest` (ID-to-directory mapping). `token` takes `--extraction-manifest`; `lavila` takes `--probe-dir` generated by `cuhkx-lavila-check`. The real LaViLa identity check is retained. Default neural training uses CUDA and four CPU threads; the original four GiB allocation cap is retained, with eight GiB for thermal.

Each family writes `fold0_banks.npz` through `fold2_banks.npz`. Each file contains `inner_sample_ids`, `outer_sample_ids`, `inner_users`, `outer_users`, `expert_names`, `inner_probability_bank`, `outer_probability_bank`, and `inner_fold`. The source bank is formed from three disjoint inner predictions. Individual fitting receipts and checkpoints are written beside it in the user's workspace.

## MMAct: 15 experts

Run the following stages through `run.py`, consulting forwarded `--help` for their input and output paths:

1. `mmact-sensor-cache`, `mmact-strong-features`, `audit-mmact-strong-cache`, and `mmact-mc3-features` prepare and verify sensor/video features.
2. `mmact-strong-teacher-train` trains the twelve base experts; `mmact-teacher-oof` constructs their source OOF bank.
3. `mmact-input-cache` creates native visual, skeleton and IMU inputs. `mmact_input_audit.py --cache-root ... --input-manifest ... --output ...` verifies the arrays; `prepare-mmact-source-normalizer` fits source-only IMU statistics.
4. `mmact-extra-teachers` trains the three additional experts. `mmact-teacher-merge` merges all fifteen, preserving their order and availability masks.
5. `mmact-teacher-compile-refined` runs the retained teacher target compiler.

The merged input to the main PRISM method is `teacher_bank.npz`, accompanied by `geometry_features.npz`. The required annotation, sensor-coverage, archive-inventory and input manifests are private inputs generated from the locally held dataset.

## MM-Fit: six experts

1. `mmfit-sensor-cache` prepares five-second sensor windows. TEST labels are never opened; source and validation labels are retained separately.
2. `mmfit-rgb-benchmark-cache` and `mmfit-rgb-benchmark-finalize-cache` prepare and verify the RGB/pose inputs.
3. `mmfit-rgb-benchmark-train` trains the RGB, pose and IMU teachers; `mmfit-strong-features` extracts the two strong video representations; `mmfit-strong-benchmark-train` trains their classification heads and the joint head.
4. `mmfit-fullroute-oof` creates the source OOF bank. `mmfit-fullroute-compile` constructs the complete teacher targets.

The expert order is `rgb`, `pose`, `imu`, `videomaev2_large`, `vjepa2`, `joint`. Source probabilities are in `oof/train_oof_bank.npz`; selection and target probabilities are in `teacher_bank_source_validation.npz` and `teacher_bank_unlabeled_test.npz` from the strong teacher stage.

## Export to the main PRISM interface

`export_bank.py` writes `expert_bank`, `expert_bank_dtype`, `expert_names`, `record_id` and dataset metadata. Roles are `source`, `selection`, and `posterior`; posterior export rejects label inputs. Metadata JSON must already follow the explicit bank ID order and contains only:

| Dataset | Metadata fields |
|---|---|
| CUHK-X | `record_id`, `users`, `dates`, `starts`; the source partition is exported from the bank |
| MMAct | `record_id`, `subject`, `scene`, `session`, `start_ms`, `end_ms`, `ordinal`, `geometry` |
| MM-Fit | `record_id`, `workout`, `time`, `descriptor` |

Supply source/selection labels with `--labels` as a separate aligned NPY or JSON vector. MMAct `--geometry` accepts the matching geometry archive. MM-Fit selection/posterior export requires `--ids`, an explicit JSON ID vector matching the per-expert arrays. The ID vector is generated from the same user-held input index, projecting only the relevant split and identity field.

```bash
python experiments/teachers/export_bank.py --dataset mmact --role posterior \
  --bank work/mmact/teacher_bank.npz \
  --geometry work/mmact/geometry_features.npz \
  --metadata work/mmact/target_metadata.json --output work/mmact/posterior.json
```

For CUHK-X, repeat `--bank` seven times in the table's family order and select `--fold 0`, `1`, or `2`. The exporter verifies all 23 names. MMAct verifies all fifteen names and masks; MM-Fit verifies all six names. Feed the resulting source/selection/posterior JSON files into the repository's target-building CLI.

The release is verified with dependency imports, forwarded CLI help and synthetic numeric checks; full teacher fitting requires the user-held datasets and local pretrained assets.
